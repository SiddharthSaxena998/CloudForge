# Own Dockerfile, app port and the "is it answering?" check

## Own Dockerfile
If the project root has a `Dockerfile`, CloudForge builds **that** instead of generating one.
- Works for any language or stack (FastAPI, Ruby, Java, multi-stage builds ...).
- CloudForge-written Dockerfiles start with `# Generated by CloudForge ...` and are regenerated on
  every deploy. A Dockerfile without that line is yours and is never overwritten.
- Saving `Dockerfile` in the dashboard's Files editor also makes it yours (the marker line is removed).
- Build log shows: `Using your own Dockerfile. App port: 8000 (from EXPOSE)`.
- Safety: a `Dockerfile` that is a symlink in an uploaded archive is ignored, and CloudForge no longer
  writes through such a link (it could have overwritten a file of the server).

## App port
Which port does the app listen on inside its container? Order of precedence:
1. Project -> Overview -> **App port** (empty = auto)
2. the `PORT` environment variable of the project
3. the first `EXPOSE <port>` line of your own Dockerfile
4. framework default: 3000 (Node, Next.js, Flask, Django, Go), 80 (React build, static HTML)

The app also receives the chosen port as `PORT` (Heroku style), so `listen(process.env.PORT)` works.
Changes apply on the next deploy.

## Port check after deploy
After the container starts CloudForge waits up to 25 s for the port to answer and writes to the build log:
- `The app is answering.` - all good
- `The app stopped right after starting. Open Containers -> Logs ...` - it crashed
- `The app is running but nothing answers on port N ...` - wrong port: set App port and redeploy
The deployment still counts as running in the last case (some apps need longer to boot).

## Test
Use `dockerfile-test.zip` (Python static server on port 8000 with its own Dockerfile):
1. New project -> upload it -> Deploy. Log: `Using your own Dockerfile ... (from EXPOSE)` and `The app is answering.`
2. Files -> Dockerfile -> delete the `EXPOSE 8000` line -> Save -> Deploy: warning "nothing answers on port 3000".
3. Overview -> App port = 8000 -> Save -> Deploy: works again.
